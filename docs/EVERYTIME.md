# 에브리타임 시간표 불러오기 — 만들지 않기로 한 결정과 근거

2026-09-27 결정: **에브리타임 공유 링크는 읽지 않는다.** 시간표 입력은 **.ics 파일 가져오기 + 직접 입력**으로 한다
(`lib/data/ics.ts`, `components/onboarding/IcsImport.tsx`). 구글 캘린더 연결은 다음 단계.

## 확인한 사실 (2026-09-27)

| 항목 | 결과 |
|---|---|
| `https://everytime.kr/robots.txt` | `User-agent: *` / `Disallow: /` — 허용은 루트(`/$`)와 광고·파비콘 파일뿐. 공유 페이지(`/@…`)는 모든 에이전트에 막혀 있다 |
| 서버에서 본인 공유 링크 요청 (curl, 우회 없음) | **403** `The server detected abnormal access and all your requests have been blocked. Please access the website(everytime.kr) with the browser.` |
| 브라우저 경로로 받은 HTML (리뷰어 확인) | 시간표 자리(`tablehead`, `tablebody`)가 **비어 있는 셸**. 데이터는 `api.everytime.kr`에서 XHR로 오고 `timetable.tableload.js`가 DOM과 픽셀 스타일을 만든다. `<meta name="robots" content="noindex">` |

즉 서버가 링크를 한 번 읽는 방식으로는 **읽을 것이 없고**, 읽으려면 헤드리스 브라우저로 차단을 넘어야 한다.
이는 이 프로젝트가 이미 배제한 우회(사람 흉내·차단 회피)다. `api.everytime.kr` 호출 형태는 일부러 조사하지 않았다.

## 참고 자료가 실제로 말한 것

- 원타임 기사(disquiet.io/articles/PWs5W2): **Selenium**으로 렌더링한 뒤 DOM의 `top`/`height`를 읽었다. 9시 = 450px, 1시간 = 50px,
  요일 열 폭 94/79/67px. 5분 단위는 "조금의 차이가 있어" 버리고 30분 단위로 반올림했다.
  공식 `Math.ceil((height − 1) / 25)`에 기사 자신의 실측(1시간 15분 = 64px)을 넣으면 90분 — **+15분 오차**.
- 네이버 블로그(2020, .NET WebBrowser): 로그인한 브라우저 창을 **1920px로 늘린 뒤** 읽었다. 1시간 = **30px**.
  좁은 창에서는 레이아웃이 달라져 비율 계산이 깨진다고 적었다.
- 두 측정이 40% 다르다 → 픽셀 상수는 사이트 불변량이 아니라 **뷰포트 폭과 그때 버전의 함수**다.
- OCR(캡처 이미지 인식): 원타임이 Tesseract·Clova OCR을 시도했다가 **포기**했다(글자 크기, 이미지 크기·형태 제각각, 비용).

## 이 서비스에서 특히 위험한 것 — 오차의 방향

우리는 "수업이 끝나면 공항으로 출발할 수 있다"를 계산한다.

| 잘못 | 출발 가능 창 | 결과 |
|---|---|---|
| 수업이 실제보다 **많거나 늦게 끝남** | 좁아짐 | 탈 수 있는 항공편 일부를 놓침 — 불편하지만 **안전** |
| 수업이 **빠지거나 일찍 끝남** | 넓어짐 | 못 타는 항공편을 추천 — **피해** |

그래서 .ics 가져오기에서도: 종료 시각은 늦은 쪽으로만 반올림, 수업 후보는 상한으로 자르지 않음,
`EXDATE`는 패턴을 유지하고 취소 날짜를 표시, 격주는 매주로 접지 않고 건너뜀.

## .ics 가져오기 규칙 요약

- 파일은 브라우저에서만 읽는다(서버 전송 없음). 1MB 상한. `BEGIN:VCALENDAR`로 시작하지 않으면(다른 인코딩 포함) 파일 단위로 거부.
- `VEVENT`의 직계 속성만 읽는다 — `VALARM`의 `DURATION`, `VTIMEZONE`의 `DTSTART`·`RRULE`은 무시.
- 시각: `Z`·UTC 계열은 전체 타임스탬프에 +9시간(날짜·요일도 바뀜), `Asia/Seoul`은 그대로,
  **floating 시각은 벽시계 그대로 한국 시각으로 본다**(기기 시간대로 옮기지 않는다 — 해외에서 열어도 같은 값). 그 밖의 TZID는 사유와 함께 건너뜀.
- `FREQ=WEEKLY` → 수업 후보. `BYDAY`가 없으면 `DTSTART`의 요일. `INTERVAL≠1`·다른 FREQ·일요일·지난 `UNTIL`/`COUNT`는 사유와 함께 건너뜀.
  `UNTIL`은 KST로 바꾼 뒤 비교. 끝이 없는 반복은 주간 패턴으로 저장.
- `RECURRENCE-ID`(옮겨진 회차) → 원 패턴은 두고 그 회차를 일회성 일정(`kind='수업'`)으로 더함. 중복 키는 `UID + RECURRENCE-ID`.
- `STATUS:CANCELLED` → 건너뜀.
- 종일 일정은 시작 날짜만 저장(`VALUE=DATE`의 `DTEND`는 배타적 — 기간을 계산하게 되면 `DTEND − 1일`).
- 일회성 일정은 오늘부터 120일 안만, 500건 상한(가까운 날짜부터). 수업 후보가 100개를 넘으면 파일 전체 거부.
- 설명이 빈 일정은 `checkEvent`를 통과할 때까지 고를 수 없다(한 건의 CHECK 위반이 배치 전체를 실패시키지 않게).

## 다시 검토한다면 — 착수 전 최소 조건

1. 이용약관 확인을 **착수 전 게이트**로(robots `Disallow: /` + `noindex`를 넘는 일이다)
2. Next.js 서버가 아닌 별도 워커의 헤드리스 브라우저
3. 뷰포트 고정 + 픽셀 상수 재실측(2019–21년 값은 쓰지 않는다)
4. 종료 시각은 늦은 쪽으로만 반올림
5. 파싱 0건·부분 파싱 감지(절반만 맞게 읽으면 오류 없이 그럴듯한 틀린 시각이 저장된다)

## 설계 구현 계획서(`design/설계 구현 계획서.dc.html`) 고칠 문구

`.dc.html`은 디자인 도구 산출물이라 코드 쪽에서 편집하지 않는다. 디자인 도구에서 아래로 바꾼다.

- **§2(5분 정밀도)** — "5분 단위로 반올림한다(우리 시간표는 5분 단위라 30분 반올림 불필요)" →
  "픽셀 방식은 5분 정밀도를 낼 수 없다(1px ≈ 1.2분, 출처 기사도 30분 단위로 포기). 이 방식은 쓰지 않는다."
- **§5(대체안)** — "허용되지 않으면 시간표 캡처 이미지 인식으로 대체" →
  "대체안은 .ics 파일 가져오기와 직접 입력이다(OCR은 출처 기사가 시도 후 포기)."
- **§6(구현 설계)** — "서버에서 한 번 읽는다" 전제 전체 →
  "공유 페이지는 robots `Disallow: /`·`noindex`이고 서버 요청은 403, 받은 HTML은 빈 셸이다. 만들지 않는다 — docs/EVERYTIME.md."
- 화면 시안의 "에브리타임 링크로 불러오기" 카드 → ".ics 파일로 불러오기"와 "에브리타임은 파일 내보내기를 지원하지 않아 직접 입력해 주세요" 안내.
