1. 서비스 요약

한국 사용자가 거주지·수업 시간표·일정·지난 방문 기록을 입력하면, 목적지와 출발 가능 시각에 맞춰 어느 공항에서 어느 편을 타는 게 가장 빠른지를 총 소요시간 순으로 보여준다. 입력은 대화형 화면으로 받고, 모든 사실 정보(편명·시각·공항·소요시간)는 DB에서만 가져온다. 1차 범위는 대한민국 국내선이며, 다른 국가는 MVP 안정화 뒤 관리자(최성빈) 승인을 거쳐 연다.

2. 설계 원칙

  • DB가 사실, AI는 문장: AI는 DB 결과를 문장으로 다듬기만 한다. 답에 나온 편명·시각·장소·소요시간·날짜를 코드(lib/ai/verify.ts)로 DB 값과 대조하고, 하나라도 다르거나 검증 중 예외가 나면 표로 대체한다(fail-closed).
  • AI는 요청할 때만: 사용자가 버튼을 눌렀을 때만 서버 라우트(/api/ai)에서 호출하고, 도구는 주지 않는다. 호출마다 ai_calls에 제공자·요청/서빙 모델·대조 내역을 남긴다.
  • 공식 데이터만: 운항은 한국공항공사·국토교통부 TAGO(공공데이터포털), 이동 시간은 카카오모빌리티(차량)·ODsay(대중교통). 봇 감지를 우회하는 브라우저 조회는 쓰지 않는다. 재시도·대기는 공식 API 호출 한도를 지키는 용도로만 둔다.
  • 추정하지 않기: 값이 없으면 "아직 없어요"로 안내하고, 샘플 값은 화면에 "화면용 샘플 데이터"로 표시한다. 기록은 사용자가 확인(다녀왔어요)해야 방문 기록이 된다.
  • 모바일 우선 PWA: 레이아웃은 논리 해상도(pt/dp) 기준, Safe Area 반영, 고정 비율을 가정하지 않는다. 기준 폭 393pt(휴대폰)·1440px(PC), 980px 이상에서 대화 화면 오른쪽 정보 패널 고정.

3. 현재 구조

3.1 기술 스택

Next.js 16(App Router, proxy.ts가 기존 middleware 역할) · Supabase(서울 리전, 인증·Postgres·RLS로 사용자별 분리) · Tailwind · Claude API(claude-opus-5, 서버 측 대체 모델 fallbacks: "default") · Playwright E2E · 단위 테스트(lib/__tests__).

4. 최근 수정사항

4.1 코드에 반영됨

  • 행정구역 2026-09 기준: 전남광주통합특별시(2026-07-01), 인천 구 개편(제물포·영종·서해·검단구), 화성시 4개 구, 대구 군위군. 시·도 수는 코드가 직접 센다(16개).
  • 운항: 샘플 편 삭제, TAGO 요금 추가, 선택한 편을 trips에 따로 복사해 동기화로 편이 지워져도 기록 유지. 결과 카드에 출처·확인 날짜, 7일 이상 지난 스케줄은 경고.
  • 이동 시간: 시각대(depart_band) 도입. 맞는 시각대가 없으면 any 값을 쓰고 "조회 시점의 실시간 교통" 안내를 표시. 대중교통 샘플 삭제, 값이 없으면 안내 문구.
  • 방문 기록: 지난 여정은 자동 승격하지 않고 확인 대기로 보여준 뒤 [다녀왔어요]만 기록. [안 갔어요]는 visit_dismissed_at으로 기억. 타임라인 파일은 브라우저에서만 읽고 추정 여정만 전송(50MB 상한).
  • AI: 제공자·모델 기록, 서버 측 대체 모델 표시, 거절·형식 오류·제공자 무응답 구분, 금액·날씨·지연·연락처는 값과 무관하게 차단.
  • 개인정보: 위치 동의 철회 시 방문 기록 즉시 삭제(1초 안의 연속 탭은 무시), JSON 내보내기(1,000행 상한을 넘도록 나눠 조회), delete_my_account RPC.

4.2 디자인에만 있음 (구현 필요)

  • 에브리타임 시간표 불러오기 (가입 4단계, 수업 시간표 탭): 공유 링크 안내 4단계 → 링크 입력·붙여넣기 → 과목 미리보기(중복은 해제, 겹침 경고, 시간 없는 온라인 강의는 선택 불가) → 선택 과목 추가. 비공개 시간표 오류 안내. 6장 참고.
  • 캘린더 연결 (가입 4단계, 내 데이터): 화면에는 "준비 중". 구글 캘린더 읽기 전용 또는 .ics 가져오기.

5. 앞으로의 방향 (단계별)

단계 작업 완료 기준
P1 데이터 채우기시각대별 차량 이동 시간 재계산(카카오 미래 운행 길찾기, 4개 band). ODsay 키로 대중교통 실측. 상세 주소 지오코딩 → 좌표 기준 계산. 행정구역을 행정안전부 행정표준코드(adm_code)로 교체.추천 결과에서 any fallback 비율 5% 미만, 대중교통 결과 표시, npm run doctor 출처 분포 확인.
P2 입력 편의에브리타임 불러오기(6장). .ics 가져오기 → 구글 캘린더 OAuth(읽기 전용). 가져온 일정은 source로 구분.디자인과 같은 흐름, 파서 단위 테스트, 실패 시 안내 문구, E2E 추가.
P3 운영 준비SMTP 연결(인증 메일 한도), ANTHROPIC_API_KEY 설정, 운항 동기화 cron 주기·실패 알림, 동계 스케줄 공개(10/24 이후) 대응, 유출 비밀번호 차단 설정.실제 사용자 가입·로그인, AI 요약 검증 통과율 기록, 동기화 실패 시 알림 수신.
P4 법무·출시위치기반서비스사업 신고 여부 확인(방송통신위원회), 위치정보 이용약관·개인정보 처리방침, 에브리타임 이용약관 검토.검토 결과 문서화, 동의 문구 버전(CONSENT_VERSION) 확정.
P5 확장국제선(인천·김포 국제선 스케줄), 다른 국가 오픈은 관리자 승인 화면과 함께. 출발 전 알림.관리자 승인 기록이 남는 국가 활성화 흐름.

6. 에브리타임 불러오기 구현 설계

에브리타임은 공식 API가 없다. 사용자가 시간표를 "전체 공개"로 두고 공유 URL(everytime.kr/@…)을 복사하면 로그인 없이 볼 수 있는 웹 페이지가 나온다. 이 페이지를 사용자가 준 링크에 한해 서버에서 한 번 읽는다. 우회 기법(사람 흉내, 차단 회피)은 쓰지 않는다. 출시 전 이용약관을 확인하고, 허용되지 않으면 시간표 캡처 이미지 인식으로 대체한다.

  1. 라우트: POST /api/import/everytime { url }. 로그인 필수, 사용자당 분당 3회 제한, 요청 타임아웃 10초.
  2. 검증: 정규식 ^(https?://)?(www\.)?everytime\.kr/@[A-Za-z0-9]{8,}/?$. 다른 호스트로의 리다이렉트는 따라가지 않는다(SSRF 방지).
  3. 파싱: 시간표 표는 9:00이 top 450px, 1시간 50px. 요일 열 폭으로 요일 수를 판단(월–금 94px, 월–토 79px, 월–일 67px). 블록마다 top·height로 시작·종료를 계산하고 5분 단위로 반올림한다(우리 시간표는 5분 단위라 30분 반올림 불필요). 과목명·강의실은 블록 안 텍스트. 이 수치는 외부 기사 기준이므로 실제 페이지로 확인하고 docs/UNVERIFIED_VALUES.md에 기록한다.
  4. 응답: { semester, items: [{ name, place, days, start, end, online }] }. 저장하지 않고 미리보기만 반환한다.
  5. 저장: 사용자가 고른 과목만 class_timetable에 source='everytime'으로 넣는다. 링크와 원본 HTML은 저장하지 않는다. 중복 판정은 과목명+요일+시작 시각.
  6. 실패 처리: 비공개(표 없음), 형식 불일치(파싱 0건), 네트워크 오류를 구분해 디자인의 안내 문구로 보여준다. 파서 결과가 0건이면 로그를 남겨 구조 변경을 감지한다.
  7. 테스트: 저장한 샘플 HTML(월–금, 월–토, 5분 단위 시작, 온라인 강의 포함)로 파서 단위 테스트. E2E는 라우트를 목(mock)으로 대체.

8. 디자인–코드 동기화 방식

  • 디자인 원본은 이 프로젝트의 .dc.html 3개이며, 저장소 design/에 복사해 둔다. 화면 문구·상태는 디자인을 기준으로 하고, 코드에서 바꾼 경우(예: 30일 뒤 삭제 → 즉시 삭제) 디자인을 다시 맞춘다.
  • github.md의 화면–파일 표를 기준으로 동기화한다. 푸시 후 커밋 ID를 기록하면 다음 동기화에서 바뀐 파일만 비교할 수 있다.
  • 샘플 값을 쓰는 화면은 반드시 "화면용 샘플 데이터" 태그를 붙이고, 실제 값으로 바뀌면 태그가 자동으로 사라지게 is_sample로 판단한다.
